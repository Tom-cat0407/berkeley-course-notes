# 写作规范

本仓库用于个人课程学习整理。以下约定用于保持课程结构一致，并让笔记内容可复现。

## 1. 目录与命名

- 课程目录固定为 `courses/<course-code>/`，`<course-code>` 使用官方课程代码的小写英文形式。
- 课次目录使用 `lectures/NN-topic/`：`NN` 从 `01` 开始补零，`topic` 使用英文小写短横线（kebab-case）。
- 文件名与目录名优先使用英文小写短横线；`README.md` 及语言/工具的标准文件名（如 `__init__.py`、`pyproject.toml`）按惯例保留，不使用空格或中文。
- 每节课的笔记、示例、练习和素材需要时分别放在课次目录的 `notes/`、`examples/`、`practice/`、`assets/`，与课次 README 并列；`labs/`、`homework/`、`projects/` 位于课程目录。
- 短课可以只有一页 `README.md`；内容较长时用短 README 作入口，正文按主题拆到 `notes/`，不强制所有课次使用同一组文件。
- `practice/` 中题目与答案分文件，例如 `exercises.md` 与 `solutions.md`；题目页只写题目和完成标准。
- `assets/` 只在有图片、数据等真实素材时创建。
- 只在有真实内容时创建目录，不用空目录或 `.gitkeep` 占位。

## 2. 课程 README

每门课程必须有 `courses/<course-code>/README.md`，至少包含：

- 学期与课程版本；
- 官方课程主页及相关链接；
- 先修知识；
- 环境、依赖安装和运行方式；
- 学习进度（自学 Module 或官方课次）及真实学习状态；已有课次笔记时列出课次目录。

课程进度只在该 README 维护，根 README 和 `courses/README.md` 不重复单门课程的详细状态。可依据真实教学大纲登记尚未开始的 Module 或课次，状态写“未开始”“进行中”或“已完成”，不虚构完成情况。课次笔记不重复记录状态。

### 自学 Module 与官方 Lecture

课程可采用自学 Module（按该课程大纲编号）或官方课次组织学习。采用 Module 时，Module 编号由该课程大纲定义，并在课程内保持固定；课次 README 可同时记录所属 Module 与官方来源。学习进度集中在课程 README。

## 3. 课次笔记

课次可以用一页 README，也可以用“短 README + `notes/` 分主题笔记”。短 README 只保留目标、阅读顺序、练习/参考入口和回顾问题，不复制笔记正文；长课的每篇笔记应有回课次入口及前后篇导航。

课次笔记按以下顺序组织，不适用的小节可以删除：

1. 学习目标：用可验证的动词描述，例如“能解释”“能实现”“能推导”。
2. 前置知识：列出需要的概念或前置课次。
3. 核心讲解：说明是什么、为什么这样设计、适用边界。
4. 示例 / 推导：保留关键步骤、代码和结论，确保他人能复现。
5. 运行方式与预期结果：有可运行内容时记录环境、命令和真实输出。
6. 易错点：写明错误原因和修正方法。
7. 练习：标明难度和答案/提示位置。
8. 回顾：用问题检查自己是否真正掌握。
9. 参考：列出官方材料、教材位置和访问日期。

补充约定：

- 完整代码或较完整的伪代码放 `examples/`，正文只保留必要短片段并链接到示例；同一实现不要同时在正文和脚本中维护两份。
- 伪代码要与可运行代码分开标注，明确未实现、不可运行，不写成 `.py` 程序，也不提供虚假的运行命令或预期输出。
- 练习题目只写题目与完成标准，答案与理由放独立答案页，题目页不剧透。
- 示例明确区分真实执行结果、假设轨迹和模型生成的解释，不把教学说明写成真实思维链。

## 4. 代码与运行

- 依赖按课程管理，在课程 README 或课次笔记中记录安装命令和版本。
- 路径、变量名、函数名等标识符使用英文；注释解释关键概念和“为什么这样做”，避免逐行翻译代码。
- 运行结果必须是实际输出。未运行或未验证的内容要明确标注，不能写成已通过。
- 不提交 `.env`、密钥、令牌或个人信息。需要环境变量时提交 `.env.example`，其中的值应为空值或示例值。
- 不提交虚拟环境、编译产物、缓存、依赖目录和大体积生成文件。

## 5. 链接、引用与版权

- 本地链接使用相对路径，并在提交前逐一点开确认；链接文字应说明目标内容。
- 首次出现的官方资源优先给出原始链接，而不是网盘或二手转载。
- 引用教材、课件、题目或图片时标明来源；不要整段复制受版权保护的课程材料，必要时只做简短摘录并链接原文。
- 明确区分课程官方表述和个人理解。个人推导或猜测应标注为个人理解。

## 6. 模板使用

新增课程或课次时，从 [课程模板](../templates/course-readme.md) 或 [课次模板](../templates/lesson-readme.md) 复制；复制命令见 [课程索引](../courses/README.md)，均在仓库根目录执行。模板同时使用可选段落和占位符说明，复制后：

1. 替换全部 `{{...}}` 占位符；
2. 先选定组织方式（单页 README，或短 README + `notes/`），再删除模板使用说明、未选用的段落和不适用的小节；
3. 把代码格式中的路径示例改成真实文件，再写成 Markdown 链接。

模板中的路径和 URL 继续用代码格式展示，避免实例化前产生坏链接；实例化后不要保留这些占位链接。

## 7. 提交前检查

- [ ] 目录结构和资源位置符合课程与课次两级约定。
- [ ] 长课 README 保持为短入口，分主题笔记可通过阅读顺序或前后导航到达。
- [ ] 所有非模板 Markdown 本地链接都能解析到真实文件或目录，锚点存在。
- [ ] 新增文件中的模板占位符已全部替换，未使用的可选段落已删除。
- [ ] 练习与答案分开，伪代码已标注不可运行，假设轨迹或未验证结果没有写成实际输出。
- [ ] 课次、日期、完成状态和运行结果均与实际一致。
- [ ] 没有提交 `.env`、密钥、虚拟环境或构建产物。
- [ ] 新增课程已在 [课程索引](../courses/README.md) 中登记。
