# 写作规范

本仓库用于个人课程学习整理。以下约定用于保持课程结构一致，并让笔记内容可复现。

## 1. 目录与命名

- 课程目录固定为 `courses/<course-code>/`，`<course-code>` 使用官方课程代码的小写英文形式。
- 课次目录使用 `lectures/NN-topic/`：`NN` 从 `01` 开始补零，`topic` 使用英文小写短横线（kebab-case）。
- 文件名与目录名优先使用英文小写短横线；`README.md` 及语言/工具的标准文件名（如 `__init__.py`、`pyproject.toml`）按惯例保留，不使用空格或中文。
- 每节课的示例、练习和素材分别放在课次目录的 `examples/`、`practice/`、`assets/`，与课次 README 并列；`labs/`、`homework/`、`projects/` 位于课程目录。
- 只在有真实内容时创建目录，不用空目录或 `.gitkeep` 占位。

## 2. 课程 README

每门课程必须有 `courses/<course-code>/README.md`，至少包含：

- 学期与课程版本；
- 官方课程主页及相关链接；
- 先修知识；
- 环境、依赖安装和运行方式；
- 课次目录及真实学习状态。

课程进度只在该 README 维护，根 README 和 `courses/README.md` 不重复单门课程的详细状态。可依据真实教学大纲提前登记未开始课次，状态写“未开始”“进行中”或“已完成”，不虚构完成情况。课次笔记不重复记录状态。

## 3. 课次笔记

课次笔记按以下顺序组织，不适用的小节可以删除：

1. 学习目标：用可验证的动词描述，例如“能解释”“能实现”“能推导”。
2. 前置知识：列出需要的概念或前置课次。
3. 核心讲解：说明是什么、为什么这样设计、适用边界。
4. 示例 / 推导：保留关键步骤、代码和结论，确保他人能复现。
5. 运行方式与预期结果：有可运行内容时记录环境、命令和真实输出。
6. 易错点：写明错误原因和修正方法。
7. 练习：标明难度和答案/提示位置。
8. 回顾：用问题检查自己是否真正掌握。
9. 参考：列出官方材料、教材位置和访问日期。

## 4. 代码与运行

- 依赖按课程管理，在课程 README 或课次笔记中记录安装命令和版本。
- 路径、变量名、函数名等标识符使用英文；注释解释关键概念和“为什么这样做”，避免逐行翻译代码。
- 运行结果必须是实际输出。未运行或未验证的内容要明确标注，不能写成已通过。
- 不提交 `.env`、密钥、令牌或个人信息。需要环境变量时提交 `.env.example`，其中的值应为空值或示例值。
- 不提交虚拟环境、编译产物、缓存、依赖目录和大体积生成文件。

## 5. 链接、引用与版权

- 本地链接使用相对路径，并在提交前逐一点开确认；链接文字应说明目标内容。
- 首次出现的官方资源优先给出原始链接，而不是网盘或二手转载。
- 引用教材、课件、题目或图片时标明来源；不要整段复制受版权保护的课程材料，必要时只做简短摘录并链接原文。
- 明确区分课程官方表述和个人理解。个人推导或猜测应标注为个人理解。

## 6. 模板使用

新增课程或课次时，从 [课程模板](../templates/course-readme.md) 或 [课次模板](../templates/lesson-readme.md) 复制；复制命令见 [课程索引](../courses/README.md)，均在仓库根目录执行。复制后：

1. 替换全部 `{{...}}` 占位符；
2. 删除模板使用说明和不适用的小节；
3. 把代码格式中的路径示例改成真实文件，再写成 Markdown 链接。

模板用代码格式展示未实例化链接，是为了在替换前不产生坏链接；复制后不要保留这些占位链接。

## 7. 提交前检查

- [ ] 目录结构和资源位置符合课程与课次两级约定。
- [ ] 所有非模板 Markdown 本地链接都能解析到真实文件或目录。
- [ ] 新增文件中的模板占位符已全部替换。
- [ ] 课次、日期、完成状态和运行结果均与实际一致。
- [ ] 没有提交 `.env`、密钥、虚拟环境或构建产物。
- [ ] 新增课程已在 [课程索引](../courses/README.md) 中登记。
