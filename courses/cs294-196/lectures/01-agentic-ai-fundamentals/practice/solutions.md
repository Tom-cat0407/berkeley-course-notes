# 练习参考答案

> [← 课次入口](../README.md) · 上一篇：[练习题](exercises.md)

以下答案用于对照思路，不是唯一写法。分类的关键是控制路径与反馈，而不是名词。

## 练习 1

### A：单次 LLM 调用

用户问题进入模型，模型返回解释，流程结束。没有外部行动、观察和下一步选择，也没有需要循环才能完成的子目标。聊天界面只是交互形式；如果这个产品在背后接入工具或 agent 模式，就要看实际控制流，不能只凭界面判断。

### B：Workflow

主路径由代码预先定义：提取、摘要、翻译、保存。OCR 是一个预设分支：程序判断文字为空后改走 OCR，再回到原来的步骤。模型负责生成摘要和翻译，但没有决定“下一步是 OCR 还是继续翻译”，所以仍是 workflow。

这个例子说明 workflow 可以有分支和工具。即使代码里有 `if`、`while` 或重试，只要路径规则由开发者预先写定，就不因为“有循环”自动变成 agent。

### C：LLM Agent

模型在运行时查看状态和上一步观察，然后选择一个工具；执行结果回到模型，模型再选择下一个工具。执行路径不是预先写死的，停止也结合了模型判断和步数上限。

如果 C 的实现其实是固定顺序的 `if/else`，模型只负责填参数，那么它更接近 workflow。反过来，如果 B 的下一步由模型读取 OCR 结果后动态决定，那 B 就出现了 agent 特征。判断依据始终是控制权和反馈作用，而不是工具数量。

## 练习 2

### 一种参考拆解

**Goal**：找到三款当前可购买、配置可比的 MacBook，按统一口径的到手价排序，给出前三名及来源和采集时间；如果无法满足三个，说明限制。

**Actions**：

1. 明确比较范围：型号与配置、全新或翻新、地区与币种。
2. 搜索候选商品并打开商品页。
3. 提取价格、配置、成色、卖家、库存、币种、税费、运费和页面时间。
4. 统一币种与含税/运费口径，计算到手价。
5. 核对库存和来源，比较并排序。
6. 返回三个选项；不足三个时报告缺口。

**Environment**：官方商店、授权零售商、翻新商店等在线页面。

**Observations**：型号标识（芯片、内存、存储）、成色、价格、币种、税费、运费、库存、卖家、采集时间、页面链接。

**Completion condition**：三个有效且在售的可比选项，价格口径一致，来源和时间已记录；或已说明为何无法满足。停止条件还包括步数或时间预算用尽、页面无法访问、需要用户确认比较范围。

### 为什么这些条件影响“最便宜”

- **同一型号的同一配置**：不同芯片、内存或存储的机器价格不可直接比较；“最便宜”必须先限定可比配置，否则可能拿低配和顶配混排。
- **全新、翻新与二手**：成色、保修和卖家不同，价格的含义不同。翻新机可能更便宜，但不能和全新机当作同一种商品。
- **币种、税费和运费**：标价币种不同需要换算；有的价格不含税或运费，到手价才是可比较的口径。
- **库存与采集时间**：页面价格和库存会变化。已经缺货或过期的报价不应进入“当前可选”的前三名，记录采集时间才能判断信息是否仍然有效。
- **卖家与保修**：非授权卖家的低价可能伴随保修或退货限制，至少应作为观察记录下来，而不是只按数字排序。

### 用户要求不清时怎么办

先明确比较范围：想要哪一类 MacBook、是否接受翻新或二手、在哪个地区购买、是否按含税到手价比较、三个选项是否必须同配置。若无法追问，就写明假设再继续，不能暗中把不同配置、不同成色或不同币种混在一起，最后给出一个看似精确的排名。

这是任务拆解练习，不查询实时价格，也不声称已经找到真实商品。
