# 核心概念：Agent、模型与六个关键词

> [← 课次入口](../README.md) · 下一篇：[Agent Loop](02-agent-loop.md)

## 先说结论

本课讨论 **LLM 驱动的 agent**：它围绕一个目标，观察当前状态，让模型决定下一步行动，执行后读取结果，再决定下一步，直到完成或触发停止条件。

一般意义上的 agent 不一定使用 LLM；规则系统或强化学习策略也可以构成 agent。本课把范围限定在 LLM 驱动的系统，因为后续课程主要讨论这一类。

一句话区分：

> LLM 生成输出；agent 使用 LLM 反复决定并执行面向目标的行动。

## 模型是组件，Agent 是系统

LLM 的基本行为是接收上下文、生成输出：

```text
输入 → LLM → 输出
```

输出可以是一段解释、一份摘要、一段代码或一个结构化结果。模型本身不保存完整的行动历史，不会主动读取文件、运行测试或等待网页返回；这些能力要由外部系统提供。

Agent 是把模型、目标和外部行动组织起来的系统：

```text
Agent 系统
├── LLM：理解目标、推理与规划、判断下一步、解释结果
├── Goal 与约束：要完成什么、什么不能做
├── Tools / Action 接口：读取文件、搜索、运行代码、调用 API
├── State：目标、历史行动、观察、中间产物
├── Environment：仓库、网页、应用或物理世界
└── Loop 与停止条件：继续、结束或交给人
```

所以 GPT、Claude、Gemini 等模型是 agent 的一个组件，不是完整 agent。反过来说，一个 agent 系统也不一定只能使用一个模型。

**Chatbot 是交互形式，不是架构分类。** 面向用户的聊天产品可能只做单次问答，也可能接入检索、工具或 agent 模式。ChatGPT 这类产品名不能直接等同于“仅单次 LLM”；判断时要看具体系统有没有目标、行动、反馈和循环。同理，工具也不是 agent 的专利，workflow 和普通助手都可以调用工具。

## 六个关键词

| 关键词 | 含义 | 例子 |
| --- | --- | --- |
| Goal | 要完成的任务，以及范围、约束和完成条件 | 找出三个合适的实习并比较 |
| Agent / Model | 做判断的系统；LLM 常负责理解、决策和解释结果 | 根据已有观察选择下一步 |
| Action | 对外执行的操作，通常通过工具、API 或界面完成 | `search_web()`、`read_file()`、`run_tests()` |
| Environment | 行动作用的外部世界，也是观察的来源 | 招聘网站、Git 仓库、浏览器、游戏世界 |
| Observation | 行动后系统实际收到的结果 | 搜索结果、测试失败信息、网页内容、权限错误 |
| Agent Loop | 把以上部分连起来的“决策—行动—观察—更新”循环 | 搜索后打开职位页，再决定是否继续比较 |

这六个词不是并列的名词清单，而是一条运行链：

```text
Goal → Agent / Model → Action → Environment → Observation → Agent / Model → …
```

循环何时结束，取决于完成条件和外部限制，下一篇展开。

### Goal 与完成条件

Goal 不只是用户的一句话。要让 agent 能执行，至少要明确任务范围、关键约束和“什么算完成”。例如“找实习”可以继续细化为地点、时间、岗位类型、是否接受远程，以及不足三个结果时怎么办。

好的 agent 围绕 goal 工作，但不会把 goal 当成可以无限解释的愿望。完成条件越可观察，循环越容易停止，也越容易验收。

### Action 与 Observation 的区别

Action 是系统对外做了什么，Observation 是环境实际返回了什么。两者不能混为一谈：

```text
Action:      run_tests()
Observation: 3 tests failed, KeyError: password_hash
```

模型可以计划一个 action，但 observation 必须来自执行结果；计划本身不是环境反馈。

### Environment 决定行动和反馈的形状

同一个 agent 思路，在不同环境里的动作和观察完全不同：

- Coding agent 的环境是代码仓库，action 可以是读文件、改文件、运行测试，observation 是文件内容、diff 和测试输出。
- Browser agent 的环境是网页，action 可以是打开页面、点击、输入，observation 是页面内容、URL 和错误提示。
- 机器人 agent 的环境是物理世界，action 是移动或操作，observation 来自传感器。

环境也决定限制：登录、权限、网络、页面结构和现实世界的不可逆操作，都会改变 agent 能做什么。

## 场景：温哥华实习比较

用户说：

> Find three suitable software engineering internships in Vancouver and compare them.

可以拆成：

- **Goal**：找到三个当前可选、符合基本条件的软件工程实习，并按用户关心的维度比较。
- **Actions**：搜索职位、打开职位页、提取公司/职位/地点/要求/薪资、检查申请条件、继续搜索、比较。
- **Environment**：招聘网站和公司招聘页。
- **Observations**：职位是否存在、发布时间、要求、薪资、地点、申请状态。
- **完成条件**：三个满足条件的职位都已核对并比较；若不足三个，说明限制，而不是编造。

单次 LLM 可能凭训练数据给出公司名和薪资，但这些信息可能过期或并不存在。Agent 的价值在于把“找”和“核对”变成可观察的步骤；代价是更慢、更贵，也会受到网页结构、登录和反爬的限制。

这也说明 agent 的重点不是只生成一个看起来合理的答案，而是通过行动把任务推进到可检查的完成状态。最终仍然要输出结果，但结果背后有可追溯的行动和观察。

## 小结

LLM 是生成输出的模型，agent 是围绕目标组织模型、行动、环境和反馈的系统。记住这条链，再看具体产品时，先问：谁决定下一步，行动后有没有真实反馈，循环靠什么停止。
