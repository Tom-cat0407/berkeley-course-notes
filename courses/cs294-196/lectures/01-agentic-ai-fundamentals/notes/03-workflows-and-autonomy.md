# Workflow、Agent 与自主性

> [← 上一篇](02-agent-loop.md) · [课次入口](../README.md) · 下一篇：[三种执行方式的伪代码](../examples/pseudocode.md)

一次模型调用、开发者写好的 workflow、由模型决定下一步的 agent，三者容易混在一起。区别不在“用没用 LLM”或“工具多不多”，而在执行路径由谁控制、反馈是否改变下一步。

## 单次 LLM 调用

一次输入、一次输出，没有围绕外部环境的多步控制：

```text
问题 → LLM → 回答
```

它可以包一层重试、格式校验或前后处理，但这些步骤不根据环境观察改变任务路径，也没有“执行行动、读取结果、再决定下一步”的循环。适合解释概念、改写文本、单轮分类或抽取这类一次生成就能完成的任务。

聊天界面只是交互形式。一个聊天产品底层可能是一次调用，也可能接入检索、工具或 agent 模式；不能因为“看起来像 chatbot”就推断它的架构。

## Workflow：路径由开发者预先定义

Workflow 把步骤、分支、循环、并行和重试写进代码，LLM 可以是其中一步：

```text
上传 PDF → 提取文字 → 生成摘要 → 翻译 → 保存
```

如果提取不到文字就走 OCR 分支，或者失败后重试三次，它仍然是 workflow，因为这些路径在运行前已经由开发者定义。Workflow 可以有工具，也可以有 `if` 分支和 `while` 循环；“固定”指下一步的去向由代码和预设规则决定，而不是模型在运行时根据观察自由选择。

这种结构可预测、易测试、成本相对稳定，适合步骤清楚且不常变化的任务。

## LLM Agent：模型在运行时选择下一步

Agent 把目标、状态和行动接口交给模型，由模型根据当前观察选择下一步：

```text
Goal → 模型选择行动 → 执行 → 观察结果 → 模型再选择 → …
```

模型决定的不只是“生成什么内容”，还包括“接下来做什么”：继续搜索、打开另一个页面、运行测试、修改文件、请求帮助，或结束。这个选择通常发生在工具、状态和停止条件的约束之内。

## 三种方式对比

| 维度 | 单次 LLM 调用 | Workflow | LLM Agent |
| --- | --- | --- | --- |
| 执行路径 | 没有多步路径 | 开发者预先定义，可有分支和循环 | 模型根据观察动态选择 |
| LLM 的角色 | 直接生成结果 | 完成其中若干步骤 | 选择下一步并解释结果 |
| 工具 | 可选，通常不参与控制流 | 可以有 | 通常有 |
| 环境反馈 | 通常没有 | 可以进入预设分支 | 直接影响下一步 |
| 停止条件 | 返回即结束 | 由代码定义 | 模型判断，加上步数、时间、权限等外部限制 |
| 适用场景 | 单次生成足够 | 步骤稳定、强调可预测和可测试 | 路径开放、需要探索或根据反馈调整 |
| 主要风险 | 内容错误 | 覆盖不到意外情况 | 成本、延迟、不可预测和权限失控 |

边界不是绝对的。一次模型调用可以成为 workflow 的一步，workflow 也可以把某个子任务交给 agent；实际系统常是混合结构。判断一段流程是否 agentic，最实用的工程问题是：**下一步是否由模型根据反馈动态决定？** 仅凭代码里有 `while` 或工具数量多，不能下结论。

这一划分也见于 Anthropic 的工程文章 [Building effective agents](https://www.anthropic.com/engineering/building-effective-agents)；它是工程补充，不是 Berkeley 官方必读。

## 自主性不是“想做什么就做什么”

自主性更准确的定义是：

> 在给定目标和权限范围内，agent 可以自行决定完成任务所需的部分步骤。

例如“找最便宜的航班”可以允许 agent 搜索、比较、检查行李费；购票或发送邮件则可能按授权策略要求人工确认。人工确认只是控制手段之一，不是所有操作都必须审批；也可以用只读权限、允许列表、预算上限、沙箱和审计日志来限定范围。

权限范围通常包括：

- 能访问哪些数据和系统；
- 能执行哪些不可逆操作；
- 单次任务的步数、时间和费用上限；
- 哪些动作需要确认，确认后是否留下记录；
- 出错时如何停止、回滚或交给人。

自主性和约束不是对立的。没有约束的“完全自主”很难验收，也不适合接入真实系统。

## 什么时候用哪种

- 一次生成就能给出可靠答案：用单次 LLM 调用，不必引入循环。
- 步骤已知、输入相对稳定、需要可预测和可测试：用 workflow。
- 路径取决于中间结果、需要探索环境或动态选择工具：用 agent，并设置预算、权限和停止条件。
- 生产系统常见做法是混合：外层 workflow 保证关键步骤和合规检查，内层 agent 处理开放子任务。

这也解释了 agent 为什么重要：真实工作往往不是一次输入输出，而是查资料、用软件、读结果、做判断、再检查。Agent 把 LLM 从语言生成器扩展为任务执行系统。但能力增加的同时也带来成本、延迟、权限和可验证性问题，所以适用性判断比“是否用 agent”更重要。

## 结论

> An LLM generates outputs. An agent uses an LLM to repeatedly decide and execute actions toward a goal.

对本课讨论的 LLM 驱动 agent，可以写成：

```text
Agent =
  Model
  + Goal
  + Tools
  + Environment
  + State
  + Agent Loop
```

一般 agent 不一定包含 LLM；这个等式限定在本课范围。后续的 reasoning、planning、infrastructure、evaluation、multi-agent 与 safety，以及 Web 自动化、机器人和科学发现等应用，都可以挂到这套结构上继续展开。
